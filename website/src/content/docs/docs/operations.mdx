## API overview

| Task | API | Contract |
| --- | --- | --- |
| Construct | `tensor`, `empty`, `zeros`, `ones`, `randn` | Explicit shape, dtype, and device; `empty` contents are unspecified |
| Inspect | `Tensor.shape`, `.dtype`, `.device` | Metadata for a contiguous row-major tensor |
| Transfer | `.to(device)`, `.cpu()`, `.numpy()` | Explicit device transfers; NumPy export copies to host |
| Elementwise | `a + b`, `a * b` | Exact shape, dtype, and device match |
| Matrix multiply | `cx.matmul(a, b)` | Float32, 2D inputs, matching inner dimensions |
| Reduce | `cx.sum(x, axis=...)`, `max`, `mean` | Explicit axis; removes that axis from the shape |
| Activate | `cx.exp(x)`, `gelu`, `silu` | Float32 |
| Normalize | `softmax`, `rmsnorm`, `layernorm` | Float32, explicit axis; preserves shape |

Support varies by backend, particularly for `int32`. See the
[support matrix](/docs/backends/).

## Numerical behavior

- Float inputs are narrowed to `float32`; precision loss and overflow are possible.
- CPU and Metal `int32` add/multiply wrap on overflow. CUDA int32 arithmetic is
  unsupported.
- Reductions support negative axes. An empty-axis sum produces zeros; mean
  produces NaNs; max raises `ValueError`.
- Softmax subtracts the maximum before exponentiation. NaNs propagate; slices
  containing positive infinity or only negative infinities produce NaNs.
- RMSNorm and LayerNorm have no affine weights. Their `eps` must be finite,
  non-negative, and representable as float32.
- Floating-point accumulation order can differ across backends. Compare with
  numerical tolerances, not bitwise equality.

There are no tensor subtraction/division operators, implicit broadcasting,
autograd, batched matmul, or general slicing/strided execution in this API.
The [experimental kernel subset](/docs/experimental/) has its own arithmetic
rules and does not extend the ordinary tensor operators.
