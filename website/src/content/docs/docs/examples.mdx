## A small inference pipeline

The repository includes a deterministic float32 example in
[`examples/cuda_mlp.py`](https://github.com/serkanaltuntas/tensor.cx/blob/main/examples/cuda_mlp.py).
It runs matmul → LayerNorm → GELU → matmul → softmax with generated inputs and
weights. No model download is required.

Start on CPU from the repository root:

```bash
uv run --no-sync python examples/cuda_mlp.py --device cpu --repeats 3
```

After installing a CUDA-enabled build on a supported host:

```bash
uv run --no-sync python examples/cuda_mlp.py --device cuda --repeats 3
```

The script checks CPU parity and probability row sums, then prints a JSON
summary including `shape: [32, 10]`, `cpu_parity: true`, and a local latency
measurement. A missing CUDA device is an error, not a silent CPU fallback.

This is an inference mechanics example with untrained weights. It does not
train a model or demonstrate prediction quality. Its short timing is a smoke
check, not a general performance claim; see [measurement guidance](/docs/performance/).


## Embedding and causal attention

This example combines the inference primitives without downloading weights.
Save it as `inference.py`, then run `uv run --no-sync python inference.py`.
Use `--device metal` or `--device cuda` with an appropriate native build. It
compares the selected backend with CPU and reports shape `[2, 3, 8]`.

Weights are deterministic random values; this demonstrates execution and
ownership, not model quality or performance. Attention uses a synchronous
score-buffer implementation. See [inference semantics](/docs/operations/#inference).

## Inspect and reuse storage

This example uses native host profiling on CPU or CUDA and enables the bounded
memory pool only on CUDA. Save it as `runtime_tools.py` and run
`uv run --no-sync python runtime_tools.py` for CPU, or add `--device cuda` with
a supported CUDA build. An unavailable selected device is an error.

<Code code={runtimeTools.trim()} lang="python" title="runtime_tools.py" />

The JSON contains `cpu_parity: true`, native host-region counts/times and, for
CUDA, pool snapshots before and after exit. Its scratch `empty` tensor is checked
only for metadata and never read. Exit frees idle blocks; this example deletes
its participating results first, so checked-out bytes also reach zero. CPU uses
no pool. Metal host profiling and pools are not implemented.

This is a functional example, not a latency benchmark. Profiled calls include
instrumentation overhead. See [profiling and memory reuse](/docs/performance/)
for timing boundaries, DLPack exclusions and cache limits.
